# 02 物理页与虚拟地址空间

[上一课](01-boot.md) · [课程目录](README.md) · [下一课](03-processes.md)

## 本课目标

区分“拿到一块内存”和“让一个虚拟地址能访问这块内存”。阅读 [kernel.c](../../kernel.c) 的 `alloc_pages`、`map_page`、`create_page_table`、`walk_pte`、`user_access_ok`，以及 [kernel.h](../../kernel.h) 的页表标志。

## 原理与源码路线

`alloc_pages` 从链接脚本预留范围分配连续物理页，使用分配锁保护游标。它目前不提供通用释放操作。`map_page` 则把虚拟页映射到物理页；映射一个已分配页不等于再次分配其数据内存。

本项目使用 Sv32 两级页表和 4096 字节页：32 位虚拟地址分成一级索引、二级索引、页内偏移，位宽分别为 10、10、12。先查一级表找到二级表，再查叶子项得到物理页与访问标志。

`create_process` 给进程构建页表、分配或复用用户镜像页并复制镜像。不同进程可以使用相同的 `USER_BASE`，通过不同页表映射到不同物理页。当前用户镜像页统一映射为可读写执行，不是细粒度代码只读保护。

`user_access_ok` 检查用户传入的范围是否溢出、每一页是否存在、是否可由用户访问，以及是否具备所需读写权限。仅验证起始地址无法保证跨页缓冲区的剩余部分安全。

## 动手练习

1. 手算 `USER_BASE=0x01000000` 的两个索引和偏移，再对照 `map_page` 的移位掩码。
2. 找到 [user.ld](../../user.ld) 中的起始地址，确认它和 `USER_BASE` 对应。
3. 为 `user_access_ok` 的范围溢出和逐页循环各写一句注释草稿，先在笔记中解释，不必修改代码。
4. 运行 `NCPU=1 bash run.sh`，执行 `hello` 和 `selftest`，确认系统调用中的用户缓冲区能正常访问。

## 验收与思考

为什么两个进程使用同一个虚拟地址不等于共享内存？为什么一个 2 字节缓冲区也可能涉及两次页检查？

<details><summary>参考要点</summary>

`0x01000000` 的一级索引是 4，二级索引和偏移都是 0。地址翻译还取决于当前页表；共享内存需要有意映射到相同物理页。若缓冲区从一页最后一个字节开始，第二字节就在下一页。
