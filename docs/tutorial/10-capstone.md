# 10 综合实验：用证据解释自己的内核

[上一课](09-smp.md) · [课程目录](README.md) · [项目首页](../../README.md)

## 本课目标

独立完成一次功能回归、一项有边界的改进和一份能被他人复现的实验报告。完成课程不以代码行数或截图数量判断，而以是否能解释机制与证据判断。

## 第一部分：基线验收

在没有其他 QEMU 实例占用镜像时运行：

```sh
python3 scripts/smoke.py
git diff --check
git status --short
```

保存 1/2/4 核日志，记录工具版本与日期。与[验证记录](../VALIDATION.md)对照，若结果不同先报告差异，不覆盖成“全部通过”。日志是本地生成物，报告引用关键终端片段即可。

| 能力 | 应提供的证据 | 不能推出的结论 |
| --- | --- | --- |
| 设备中断 | block 子测试通过，UART 输入有响应 | 所有设备路径均无轮询 |
| 抢占 | 同核 quick/hog 顺序检查通过 | 内核可随处抢占、实时期限保证 |
| IPC | 完整 3 KiB 字节流与 EOF | 完整 POSIX 或全部关闭竞态正确 |
| SMP | 所有配置 hart 的 worker 返回匹配结果 | 线性加速、完整负载均衡、已观察迁移 |

## 第二部分：选择一项改进

以下是作业，不是仓库已经完成的能力。先写行为预期，再改代码。

| 作业 | 修改入口 | 验收要求 |
| --- | --- | --- |
| 断管回归 | `shell.c` | 按第 08 课验证 -32，并在失败路径释放 fd |
| fd 资源耗尽与恢复 | `shell.c` | 当前进程占满 8 个 fd 后再次打开失败；关闭后能重新打开 |
| 用户态查询命令 | `shell.c` | 使用现有 `get_hartid/get_ncpu/get_ticks` 增加命令并解释计数口径 |
| 管道容量实验 | `kernel.c`、实验报告 | 比较 64/256 字节容量的数据正确性，不声称未经测量的性能提升 |

不要同时修改 trap、锁和测试协议；一次只改变一个因素，保留可解释的前后差异。修改之后执行 `bash run.sh`，手动验证新增行为，再运行多核回归。

## 毕业验收

能够不照抄文档解释以下五条路径，并指向具体函数：

1. 固件如何把执行权交给内核，内核如何进入 shell。
2. 一次用户输出如何经过 syscall 和 trap 返回。
3. 一个磁盘等待者如何从 `BLOCKED` 变为 `RUNNABLE`。
4. 一个不主动 yield 的任务如何被 timer 切走。
5. 两个 hart 如何避免同时运行同一个 PCB。

报告需包含基线回归、一个新增实验和局限说明。新增实验失败也可以有学习价值，但必须保留失败证据和分析，不能把它列成已完成能力。
